# Decision record R2 — Power BI

> **Status:** Accepted 2026-08-02. Implementation landed; **end-to-end verification is still
> open** — see §5, which is the part of this record that matters most.
>
> **Epic:** AB#6450 · **Feature:** AB#6882 · **Author:** Claude Code

## 1. Decision

**Emit a PBIP project — TMDL semantic model plus authored report pages — as the primary output.
Keep the generated `.pbit` as a fallback only.**

## 2. Why the previous output failed

Not opinion. Phase 0 measured it: `report.pbit` was **4,689 bytes**, of which the authored
`Report/Layout` was **2,190**. Four flat CSVs, one lowercased `framework|area` text key joining
everything, **zero measures**, no date dimension, and no report pages. Opening it presented a
blank canvas and four tables.

The owner's verdict was "a waste of my time", and that is the correct reading of the artefact: **a
model with no measures asks the reader to build the analysis the tool was supposed to do.**

## 3. Why PBIP rather than a better `.pbit`

Because PBIP is **text**. The semantic model is TMDL and the report is JSON, so both diff, both
review in a pull request, and both can be regenerated by a later run without losing hand edits to
parts this generator does not own. A `.pbit` is an opaque zip: improving it would have produced a
better artefact that nobody could inspect, which is the same failure mode one layer up.

Concretely, the model now declares four real relationships onto framework, area and date
dimensions instead of one shared string; eleven DAX measures; a calculated date dimension with a
fact column that actually joins to it; and three authored report pages.

Lineage tags are **derived from object names**, not freshly generated. Random GUIDs would make
every regenerated project a whole-file diff and would break report visuals that reference the
previous tag — which would have quietly destroyed the reviewability that motivated the format.

## 4. Four defects only Power BI Desktop could find

Recorded because each cost real time and none is discoverable by reading the file:

1. **Desktop validates every `$schema` URL against a regex** before it opens anything, and rejects
   the whole project with `UnrecognizedSchemaVersion` on a mismatch. All three were wrong. They
   are genuinely inconsistent with each other — `pbip/pbipProperties`,
   `item/<type>/definitionProperties`, `gitIntegration/platformProperties` — and must not be
   tidied into a consistent-looking family.
2. **A TMDL `///` description precedes the object it documents**, at that object's indent. Emitted
   as the first line *inside* a measure it fails with `Unexpected line type: Property!` pointing at
   the **next** line — sending you to inspect `formatString` when the fault is the line above.
3. **`definition.pbir` version `1.0` means the classic report** (a single `report.json`). The 4.x
   versions signal the enhanced report format, where the report is a `definition/pages/` tree.
   Declaring 4.x while shipping `report.json` tells Desktop to look for files that are not there.
4. **TMDL is indentation-sensitive and the indent character is a TAB.** Converting the generator's
   here-strings to spaces produces a project Desktop refuses to open.

## 5. What is verified, and what is not — read this before closing anything

**Verified.** The TMDL parses under Microsoft's own parser —
`Microsoft.PowerBI.Tabular.dll`'s `TmdlSerializer.DeserializeDatabaseFromFolder` — returning 5
tables, 4 relationships and 11 measures. Power BI Desktop 2.156.951.0 opens the project: the title
bar reads the project name and the model loads in Import mode with all five M queries and the
`DataFolder` parameter present.

**Not verified.** The report canvas does not yet render — Desktop's ribbon throws
`Cannot read properties of undefined (reading 'customTheme')` because the generated `report.json`
config declares no `themeCollection`. Until that is fixed and the pages are seen to render, clauses
`B-01`–`B-05` are asserted against **file shape**, not against a working report.

That distinction is the whole point of `docs/design/report-conformance.md`. A generator whose
output parses is not a generator whose output is usable, and 103 previously-closed report tickets
are the evidence for treating that gap as real.
